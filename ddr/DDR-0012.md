# DDR 0012 — Coded concepts & global reference data

**Status:** Accepted · **Date:** 2026-07-04 · **Confidence:** High · **Implements:** ADR 0003

## Context
Clinical data uses coded concepts (ICD-10, SNOMED CT, LOINC, ABDM value sets). FHIR models these as
`CodeableConcept` (a system + code + display, possibly several codings). We need consistency and FHIR
validity across tenants.

## Decision
- **CodeableConcept modeling:** promoted columns `*_system`, `*_code`, `*_display` for the primary coding
  + `*_codings jsonb` for the full array.
- **Global reference schema** (`reference.code_system`, `reference.code`) is **non-tenant**, seeded, and
  **read-only** to `aiims_app`; versioned by release.

## Alternatives considered
- **Free-text clinical fields** — unsearchable, non-interoperable, unsafe. Rejected.
- **Per-tenant copies of code systems** — duplication and drift. Rejected in favor of shared global tables.
- **All codings in JSONB only** — loses cheap indexed lookup on the primary code. Rejected (hybrid instead).

## Trade-offs
Seeding/maintaining code systems is an operational task, and the hybrid stores the primary coding twice
(column + JSONB). Worth it for interoperability and query performance.

## Consequences
Consistent, FHIR-valid coded data; primary codes are indexable; full fidelity preserved in JSONB for
bundle regeneration (DDR 0005).
