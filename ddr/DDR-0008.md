# DDR 0008 — Tenant-scoped referential integrity

**Status:** Accepted · **Date:** 2026-07-04 · **Confidence:** High · **Implements:** ADR 0002

## Context
RLS filters visibility, but foreign keys must also prevent a child row from referencing a parent that
belongs to a *different* tenant.

## Decision
- Carry `tenant_id` on every scoped table and use **composite foreign keys** `(tenant_id, parent_id) →
  parent(tenant_id, id)`.
- **Unique constraints are tenant-scoped**: `(tenant_id, mrn)`, `(tenant_id, code)`, etc.

## Alternatives considered
- **Single-column FKs (`parent_id` only)** — a child could point at another tenant's parent; RLS hides it
  but integrity is violated. Rejected.
- **Global uniques** — wrong for multi-tenant (two hospitals can each have MRN "1001"). Rejected.

## Trade-offs
Composite keys require `tenant_id` in join predicates (which we want anyway for index efficiency) and add
a column to indexes. Negligible cost for correct cross-tenant integrity.

## Consequences
Cross-tenant references are structurally impossible, complementing RLS. Joins naturally lead with
`tenant_id`, aligning with the indexing strategy (DATABASE-ARCHITECTURE §12).
