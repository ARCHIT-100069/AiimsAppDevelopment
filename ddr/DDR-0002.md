# DDR 0002 — RLS enforcement: FORCE RLS, fail-closed, `SET LOCAL` context

**Status:** Accepted · **Date:** 2026-07-04 · **Confidence:** High · **Implements:** ADR 0002

## Context
Tenant isolation is the platform's core PHI safeguard and must be enforced by the database, not trusted
to application code (ADR 0002). The mechanism must be safe under connection pooling (RDS Proxy).

## Decision
- Every tenant-scoped table: `ENABLE` **and** `FORCE ROW LEVEL SECURITY`.
- Policy: `USING/WITH CHECK (tenant_id = current_setting('app.tenant_id', true)::uuid)`.
- `current_setting(..., true)` returns NULL when unset → **fail-closed** (no rows), never fail-open.
- Tenant context is set with **`SET LOCAL app.tenant_id`** inside the request transaction — transaction-
  scoped, so it is safe with transaction pooling and never leaks across pooled connections.

## Alternatives considered
- **Session-level `SET`** — unsafe with pooled connections (context bleeds between tenants). Rejected.
- **App-layer `WHERE tenant_id` only** — one forgotten clause leaks PHI. Rejected as the primary control
  (kept only as defense-in-depth).
- **Schema-per-tenant** — heavier migrations at scale (ADR 0002). Not the default.

## Trade-offs
Every access path must run inside a tenant-context transaction; a missed path fails closed (safe) rather
than leaking. `FORCE` means even the table owner is filtered, so migrations use an explicit bypass context.

## Consequences
Isolation is guaranteed at the engine. Backed by the mandatory cross-tenant isolation CI gate (DDR 0011 /
DATABASE-ARCHITECTURE §17).
