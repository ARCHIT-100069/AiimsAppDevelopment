# APDR-0014 — Contract-first OpenAPI 3.1 + API governance

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Client/server drift and inconsistent APIs are avoided only if contracts are the single source of truth and
changes are governed (Blueprint §13, BDR-0002).

## Decision
**Contract-first:** `packages/api-contracts` is the source of truth; **OpenAPI 3.1 generated** from it →
typed client, server validation, and Swagger docs stay in lockstep. **Governance:** every API change is a
reviewed PR against contracts; OpenAPI/Spectral lint enforces naming/envelope/error/pagination standards in
CI; breaking-change detection gates version bumps (APDR-0002). Endpoints map to context owners (BDR-0002);
new public endpoints need security + product sign-off.

## Alternatives Considered
- **Code-first, docs generated after** — drift, inconsistent design. Rejected.
- **Hand-written OpenAPI** — diverges from code. Rejected (generated from contracts).

## Trade-offs
Contract-first adds a design step before coding; delivers consistency, safety, and living docs.

## Consequences
No client/server drift; enforced standards; auditable API evolution.
