# APDR-0008 — Long-running operations: async 202 + operation resource

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Some operations (FHIR bundle generation, bulk import, reports, ABDM async) exceed a request's budget and
must not block or be done in the request transaction (BDR-0004/0005/0007).

## Decision
**Async pattern:** accept → enqueue (BullMQ) → return **`202 Accepted`** with an **operation resource**
`/v1/operations/{id}` the client polls; terminal state links to the result. Completion may also push via
**SSE** (APDR-0009) or **webhook** (APDR-0010).

## Alternatives Considered
- **Synchronous long requests** — timeouts, held connections/locks. Rejected.
- **Fire-and-forget without status** — clients can't track outcome. Rejected (operation resource).

## Trade-offs
Clients must poll/subscribe; keeps the API responsive and the DB unblocked.

## Consequences
Responsive API; reliable async processing with observable status.

## Dependencies
BDR-0005/0007, APDR-0009/0010.

High. ## Reversibility Medium.
