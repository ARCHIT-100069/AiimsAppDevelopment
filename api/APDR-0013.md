# APDR-0013 — Rate limiting & quotas

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
A multi-tenant PHI API must resist abuse/DoS and ensure fair use across tenants (SDR-0009), protecting the
shared database.

## Decision
**Redis-backed** rate limits per **tenant + user + IP**, per-endpoint classes (read/write/expensive),
token-bucket (burst + sustained). **429 + `Retry-After`**; abusive patterns escalate to WAF. **Quotas/tiers**
per tenant plan (Production).

## Alternatives Considered
- **No/edge-only limiting** — misses per-tenant fairness and expensive-endpoint protection. Insufficient.
- **DB-based counters** — load on the primary DB. Rejected (Redis).

## Trade-offs
Limits can reject legitimate bursts; tunable per class. Necessary for stability/fairness.

## Consequences
DB protected; fair multi-tenant use; DoS resistance.

## Dependencies
SDR-0009, Blueprint §17/§18, APDR-0004.
