# APDR-0003 — Response envelope + Problem-Details error model + validation

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Uniform responses and safe, machine-readable errors are needed across all endpoints, without leaking PHI
(SDR-0004/0010) and mapping cleanly from the backend error taxonomy (BDR-0010).

## Decision
- **Success:** resource body, or `data` + `meta` for collections; correlation-id header.
- **Errors:** **RFC 9457 Problem Details** (`type/title/status/code/detail/correlationId`, `errors[]` for
  fields). **No PHI/secrets/stack traces**; 5xx generic + correlation id.
- **Validation:** Zod from `api-contracts` at the edge → 422 with field errors (BDR-0009).

## Alternatives Considered
- **Ad hoc/varied error shapes** — poor client ergonomics. Rejected.
- **Raw framework errors** — leak risk. Rejected (SDR-0009).

## Trade-offs
A strict envelope/format is more upfront design; delivers consistency and safety.

## Consequences
Predictable client handling; no sensitive leakage; clean taxonomy→HTTP mapping.

## Dependencies
BDR-0009/0010, SDR-0009/0010, `api-contracts`.
