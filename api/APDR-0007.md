# APDR-0007 — File transfer via presigned S3 URLs

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Documents/imaging must be stored securely (SSE-KMS, per-tenant prefix, Blueprint §16) without streaming
large PHI payloads through the API.

## Decision
Files transfer **directly to/from S3 via short-lived presigned URLs**. The API issues the URL from a
metadata endpoint (`POST /v1/documents`), stores only metadata (owner, type, encounter link, checksum),
and confirms upload. Download via presigned GET. Access is **authorized + audited**; URLs are time-boxed.
DICOM/imaging use the same pattern.

## Alternatives Considered
- **Stream files through the API** — memory/bandwidth load, larger PHI surface. Rejected.
- **Public/long-lived URLs** — PHI exposure. Rejected (SDR-0004, Blueprint §16 block-public).

## Trade-offs
Two-step client flow (get URL → upload → confirm); far better security/scalability.

## Consequences
Scalable, secure file handling; API stays lightweight; presigned access is auditable.

## Dependencies
