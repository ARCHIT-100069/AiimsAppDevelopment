# APDR-0005 — Cursor pagination + allow-listed filtering/sorting

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
List endpoints over large, growing clinical data must be stable, efficient, and index-friendly (DB §12),
and must not allow arbitrary unindexed scans.

## Decision
**Cursor-based pagination by default** (`?limit=&cursor=`, `meta.nextCursor`); OFFSET only for small bounded
admin lists. **Filtering/sorting on allow-listed fields only** (`filter[...]`, `sort=-field`). All list
queries tenant-scoped (RLS) with a max `limit`.

## Alternatives Considered
- **OFFSET pagination everywhere** — drifts under inserts, slow deep pages. Rejected as default.
- **Arbitrary field filtering** — unindexed scans, DoS risk. Rejected (allow-list).

## Trade-offs
Cursors are less "jump to page N" friendly; correct for large healthcare datasets.

## Consequences
Stable, fast, index-aligned list APIs; predictable DB load.

## Dependencies
DB §12 (indexes), SDR-0009 (DoS), APDR-0003.

High. ## Reversibility Medium.
