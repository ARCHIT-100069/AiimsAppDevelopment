# APDR-0004 — API auth flow (OIDC bearer + BFF + tenant + PEP/PDP)

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Every request must be authenticated, tenant-scoped, and authorized in a fixed order (SDR-0001/0002/0003,
BDR-0012), with browsers holding no long-lived tokens.

## Decision
**Bearer OIDC access tokens** (Keycloak) on every request; browser flows via the **BFF**. Pipeline:
AuthN → tenant context (`SET LOCAL app.tenant_id`) → AuthZ (PEP guard → `authz` PDP) → validation → handler
→ audit. Machine clients use scoped client-credentials. No endpoint bypasses the pipeline.

## Alternatives Considered
- **Tokens in browser storage** — XSS risk. Rejected (BFF).
- **Per-endpoint auth code** — inconsistent, bypass-prone. Rejected (global middleware).

## Trade-offs
Fixed pipeline reduces per-endpoint flexibility — the intended safety property.

## Consequences
Uniform, unbypassable auth + tenant scoping + audit on the API surface.

## Dependencies
SDR-0001/0002/0003, BDR-0012, ADR 0008.

## Confidence
High. ## Reversibility Low.
