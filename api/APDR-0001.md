# APDR-0001 — REST + JSON, resource-oriented; GraphQL deferred

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
The frozen Blueprint (§13) mandates RESTful, versioned APIs with a consistent envelope; FHIR is a separate
boundary. We must fix the primary API style for the application/partner surface.

## Decision
Resource-oriented **REST over JSON**, contract-first (`api-contracts`), consistent across all endpoints.
**GraphQL is deferred** (may be added later as a read gateway). FHIR served only at its boundary (APDR-0012).

## Alternatives Considered
- **GraphQL now** — flexible nested reads but adds authz/caching/N+1 governance complexity; premature (Blueprint §13). Deferred.
- **gRPC external** — poor browser/partner ergonomics; internal-only if ever. Rejected for the public surface.

## Trade-offs
REST can over/under-fetch vs GraphQL; mitigated by well-designed resources + projections (BDR-0006).

## Consequences
Predictable, widely-tooled API; consistent conventions; clean FHIR separation.

## Dependencies
Blueprint §13, APDR-0012, `api-contracts`.

## Confidence
High. ## Reversibility Medium.
