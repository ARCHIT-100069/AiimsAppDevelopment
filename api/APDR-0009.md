# APDR-0009 — Realtime: SSE now, WebSockets deferred

**Status:** Accepted · **Version:** 1.0 · **Owner:** API/Backend Lead · **Date:** 2026-07-04

## Context
Clients need server→client realtime (worklist updates, notifications, operation completion) without a heavy
bidirectional stack in MVP.

## Decision
**Server-Sent Events (SSE)** for one-way server→client realtime in MVP — HTTP/ALB-friendly, simple,
authenticated + tenant-scoped, no PHI beyond the authorized tenant. **WebSockets deferred** to a real
bidirectional need (e.g. collaborative editing), which requires ALB WebSocket + sticky handling.

## Alternatives Considered
- **WebSockets now** — bidirectional but heavier infra/ops; unnecessary for MVP needs. Deferred.
- **Client polling only** — simple but chatty/laggy for notifications. SSE preferred.

## Trade-offs
SSE is one-way and has connection limits; sufficient for notifications/worklists now.

## Consequences
Low-complexity realtime within the frozen infra; clean upgrade path to WebSockets later.

## Dependencies
Blueprint §17 (ALB), SDR-0003 (tenant scoping), APDR-0004.

## Confidence
Med-High. ## Reversibility Medium.

## Phase Classification
MVP Implementation (SSE) + Future Enhancement (WebSockets).
