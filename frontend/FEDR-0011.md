# FEDR-0011 — Forms & validation: React Hook Form + shared Zod

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Clinical data entry must be correct and must not diverge from server validation (APDR-0003, BDR-0009).

## Decision
**React Hook Form + the same Zod schemas** the API validates with (`domain-types`) — one schema, both
sides. Client validation is **UX only**; server is authoritative. Show 422 field errors from Problem-Details
inline. Clinical forms support safe autosave-draft and explicit **sign/finalize by the clinician**
(Constitution); 409 conflicts surface a reconcile flow.

## Alternatives Considered
- **Separate client validation rules** — drift from server; contradictory errors. Rejected.
- **Server-only validation** — poor UX (round-trips for every field). Rejected.

## Trade-offs
Shared schemas couple client to `domain-types` (intended); consistent validation everywhere.

## Consequences
Consistent validation, good UX, server remains the source of truth.

## Dependencies
APDR-0003, BDR-0009, `domain-types`, FEDR-0005.

High. ## Reversibility Medium.
