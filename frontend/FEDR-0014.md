# FEDR-0014 — Frontend testing strategy (hooks; detail owned by TDR)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Frontend quality for a clinical app requires layered testing across web and native; full strategy is the
Testing phase's (TDR) mandate.

## Decision
- **Unit/component:** React Testing Library (web) + RN Testing Library, including **accessibility assertions**.
- **Contract:** validate the typed client against `api-contracts` (no drift).
- **E2E:** Playwright (web) + Detox/Maestro (mobile) covering the **OPD hero flow**.
- **Visual regression** for the design system; **i18n** pseudo-locale checks. Coverage gates set in TDR.

## Alternatives Considered
- **Manual QA only** — unscalable, regression-prone. Rejected.
- **E2E-only** — slow, brittle, poor unit coverage. Rejected (layered pyramid).

## Trade-offs
Multiple test types/tools to maintain; delivers confidence across platforms and the critical flow.

## Consequences
Regression safety for web + native; contract drift caught early; a11y enforced.
