# FEDR-0009 — Navigation & routing (shared route + permission model)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Web and mobile need consistent information architecture and consistent route-level authorization.

## Decision
**Web:** Next.js App Router (file-based, nested layouts). **Mobile:** Expo Router / React Navigation
(stacks + tabs). A **shared declarative route→required-capability map** drives navigation and guards on
both platforms; unauthorized routes are hidden and guarded. Deep-linking is auth- and tenant-aware.

## Alternatives Considered
- **Independent per-platform routing with duplicated guards** — drift, inconsistent authz. Rejected.
- **Fully custom router** — reinvents mature tools. Rejected.

## Trade-offs
A shared route/permission abstraction over two routers adds a thin layer; ensures consistency.

## Consequences
Consistent IA and route guards across platforms; single place to reason about access.
