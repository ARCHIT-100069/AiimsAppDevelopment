# FEDR-0006 — API integration: typed client from contracts + flags + observability

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Clients must consume the frozen API without drift and honor its envelope, errors, idempotency, and
pagination (APDR-0003/0005/0006/0014).

## Decision
A **typed client generated from `api-contracts`/OpenAPI**; web routes through the **BFF**, mobile calls
directly with a secure-storage token. Central handling of Problem-Details errors, `Idempotency-Key` on
unsafe writes, cursor pagination, 401→refresh, 409→conflict UX. **Correlation ids** propagated; client
telemetry carries **no PHI** (SDR-0010). **Feature flags** (server-driven) gate UI/integrations.

## Alternatives Considered
- **Hand-written fetch + types** — drift from the API. Rejected (contract-first, APDR-0014).
- **Per-call ad hoc error handling** — inconsistent UX/leak risk. Rejected.

## Trade-offs
Codegen pipeline to maintain; guarantees client/server lockstep.

## Consequences
No API drift; consistent, safe, observable integration across platforms.

## Dependencies
APDR-0003/0005/0006/0014, SDR-0010, ADR 0010.

## Confidence
High. ## Reversibility Medium.
