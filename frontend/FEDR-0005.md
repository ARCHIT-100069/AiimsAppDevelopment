# FEDR-0005 — State management: TanStack Query + Zustand

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
The API is the source of truth (thin client, Blueprint §8). We need robust server-state handling and a
little local UI state, consistently on web and native.

## Decision
**TanStack Query** for server state (caching, invalidation, retries, optimistic updates, background
refetch) on both platforms; **Zustand** for local UI state. **No global mutable domain store** — the query
cache is the derived view of server truth. Forms use RHF (FEDR-0011).

## Alternatives Considered
- **Redux (Toolkit)** — boilerplate-heavy; server-state libs handle caching better. Rejected (Blueprint §8).
- **Everything in a global store** — stale/duplicated PHI truth. Rejected.

## Trade-offs
Two libraries with distinct roles to learn; clean separation of server vs UI state.

## Consequences
Predictable data flow; shared hooks across platforms; less stale-data risk.
