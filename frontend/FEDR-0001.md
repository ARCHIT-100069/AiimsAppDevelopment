# FEDR-0001 — Web stack: Next.js + React + TS + Tailwind/shadcn + BFF

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
The frozen Blueprint (§8) already names Next.js/React/TS/Tailwind and a BFF token model. This FEDR ratifies
and details the web stack.

## Decision
**Next.js (App Router) + React + TypeScript**; Tailwind + **shadcn/ui** (Radix); **BFF** (Next route
handlers) mediates API calls so the browser holds no long-lived tokens (SDR-0001). Server Components for the
shell/non-PHI; rich client for the clinical app.

## Alternatives Considered
- **SPA (Vite/CRA) without BFF** — worse token security + first load. Rejected (Blueprint §8).
- **Remix/other meta-framework** — viable but Next.js is the frozen choice; no reason to diverge.

## Trade-offs
BFF adds a server hop; correct for PHI/token safety. App Router server/client split adds a mental model.

## Consequences
Fast, secure web client sharing types/validation with the backend.

## Dependencies
Blueprint §8, SDR-0001, FEDR-0003/0006.
