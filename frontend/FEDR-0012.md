# FEDR-0012 — Realtime via SSE → cache invalidation

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Worklists/notifications/operation-completion need realtime updates; the API provides SSE (APDR-0009).

## Decision
Consume **SSE**; on event, **invalidate the relevant TanStack Query keys** so the UI re-fetches server
truth (no client-authoritative PHI merges). Authenticated + tenant-scoped stream; auto-reconnect with
backoff; graceful degradation to polling. Mobile uses the same model; native push (Production) supplements
when backgrounded.

## Alternatives Considered
- **Client-side authoritative merge of pushed PHI** — risk of stale/incorrect clinical data. Rejected
  (invalidate-and-refetch instead).
- **Polling only** — laggy/chatty. Kept as fallback.
- **WebSockets now** — unneeded for one-way updates (APDR-0009). Deferred.

## Trade-offs
Invalidate-refetch adds a fetch per event vs merging; guarantees correctness/consistency.

## Consequences
Fresh, consistent UI without trusting the client to reconstruct PHI.

## Dependencies
APDR-0009, FEDR-0005/0006.

## Confidence
High. ## Reversibility Medium.

## Phase Classification
MVP Implementation (SSE) + Production (native push).
