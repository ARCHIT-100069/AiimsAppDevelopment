# FEDR-0004 — Design system, tokens, theming, accessibility, i18n

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
A clinical product needs a consistent, accessible, themeable, multilingual UI across web and native.

## Decision
**Token-first design system** (single tokens source → web + native). Web uses Tailwind + **shadcn/ui**
(Radix, accessible); native uses an RN library implementing the same tokens. **WCAG 2.1 AA** target;
**i18n framework** from day one (English first, Indian languages addable); token-driven **theming**
(light/dark, per-tenant, density, high-contrast). Color never the sole signal.

## Alternatives Considered
- **Heavy component kit (MUI/AntD)** — harder to theme for a healthcare system, larger bundles. Rejected.
- **Retrofit i18n/a11y later** — costly rework, compliance/UX risk. Rejected (build in now).

## Trade-offs
Building a token system + two renderers is upfront work; yields cross-platform consistency and inclusion.

## Consequences
Consistent, accessible, localizable, themeable UI; brand/theme changes are token edits.

## Phase Classification
