# FEDR-0002 — Mobile stack: React Native + Expo (native iOS/Android)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
The Blueprint marked mobile as "Future"; the founders now require **native-quality Android & iOS** apps.
The stack must consume the frozen API and reuse the frozen TypeScript foundations.

## Decision
**React Native + Expo (TypeScript)** for native iOS/Android from one codebase — reuses `domain-types`,
`api-contracts`, `validation`, and design tokens; accesses native secure storage/biometrics/push; delivers
native UX (not a web wrapper).

## Alternatives Considered
- **Flutter (Dart)** — forfeits reuse of the frozen TS contracts/validation and forks the language/skills.
  Rejected.
- **Separate native (Swift + Kotlin)** — best fidelity but ~2× effort for two founders; reuses nothing.
  Rejected for MVP.
- **PWA / web wrapper** — not native-quality; fails the requirement. Rejected.

## Trade-offs
RN has occasional native-module/perf edge cases vs pure native; Expo constrains some native config. Net:
one language, shared contracts, native-quality UX — the right balance for the team and timeline.

## Consequences
Native apps that share ~logic/validation with web; faster delivery; single talent pool.

## Dependencies
Blueprint "Future: Mobile", FEDR-0003/0007/0010.

## Confidence
Med-High. ## Reversibility Medium (screens re-skin; shared logic portable).

## Phase Classification
Structural Foundation (mobile platform) — an elaboration of the frozen roadmap, not a change.
