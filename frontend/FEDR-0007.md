# FEDR-0007 — Auth flow: web BFF cookie; mobile PKCE + secure storage

**Status:** Accepted · **Version:** 1.0 · **Owner:** Frontend Lead · **Date:** 2026-07-04

## Context
Token handling must match SDR-0001 (web BFF, no browser tokens) and extend safely to native, where there
is no BFF on device.

## Decision
- **Web:** Authorization Code + **PKCE** via the **BFF**; tokens in httpOnly/Secure/SameSite cookie session.
- **Mobile:** native **PKCE** with Keycloak; tokens in **Keychain/Keystore**; refresh-token rotation;
  optional **biometric** unlock (Production); logout clears secure storage + revokes.
- Both attach bearer tokens per request; tenant/role claims drive context/UI.

## Alternatives Considered
- **Tokens in web localStorage / RN AsyncStorage (plaintext)** — XSS/device-theft exposure. Rejected.
- **BFF proxy for mobile too** — unnecessary hop; native secure storage is the platform-correct approach.

## Trade-offs
Two auth implementations (web BFF vs mobile native); each is the correct pattern for its platform.

## Consequences
No exposed long-lived tokens on either platform; standard, revocable sessions.

## Dependencies
SDR-0001, ADR 0008, APDR-0004.

## Confidence
High. ## Reversibility Low.

## Phase Classification
Structural Foundation + Production (biometric, cert pinning).
