# IDR-0002 — Multi-environment (dev/staging/prod) via Terraform

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
Config drift between environments is a leading cause of "works in staging, breaks in prod" and of
security gaps. PHI must never reach lower environments.

## Decision
Three environments — **Dev** (synthetic data, no PHI), **Staging** (prod-like, synthetic/anonymized,
gated), **Production** (real PHI, hardened) — all provisioned from the **same Terraform modules**, differing
only by variables. Promotion: dev → staging (gated) → prod (approved, canary).

## Alternatives Considered
- **Hand-configured per-env infra** — drift, inconsistency. Rejected.
- **Two environments (no staging)** — no prod-like gate for integration/eval/isolation tests. Rejected.

## Trade-offs
Three environments cost more; parity + a real pre-prod gate is worth it for a clinical system.

## Consequences
No drift; PHI confined to prod; reliable promotion with real gates.

## Dependencies
IDR-0001/0012, SDR-0012 (gates).

High. ## Reversibility Medium.
