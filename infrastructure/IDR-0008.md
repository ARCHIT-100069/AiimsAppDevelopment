# IDR-0008 — S3 + CloudFront CDN

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
Documents/imaging need secure, durable storage (SDR-0004, Blueprint §16); the web app needs fast static
delivery — but **no PHI may be cached at a CDN**.

## Decision
**S3** private buckets, **Block Public Access** org-wide, **SSE-KMS**, per-tenant prefixes, **presigned-URL**
access; **Object Lock (WORM)** for audit/legally-retained data; versioning + CRR for critical buckets.
**CloudFront** fronts **only** public/static/marketing content and the Next.js static layer; **authenticated
API/PHI responses bypass the CDN** (private, no-store). ACM TLS + WAF on CloudFront.

## Alternatives Considered
- **Public buckets / long-lived URLs** — PHI exposure. Rejected.
- **CDN in front of PHI APIs** — caching PHI at the edge. Rejected.
- **Store blobs in DB** — bloats DB. Rejected.

## Trade-offs
Presigned-URL flow is a two-step client pattern; CDN split requires care; both are correct for PHI.

## Consequences
Secure PHI storage + fast static delivery, with no PHI at the edge.

## Dependencies
SDR-0004, Blueprint §16/§19, IDR-0009/0010.
