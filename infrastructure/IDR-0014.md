# IDR-0014 — DR + backup/restore + RPO/RTO targets

**Status:** Accepted (business RTO sign-off pending) · **Version:** 1.0 · **Owner:** Cloud & Infra Architect
**Date:** 2026-07-04

## Context
ADR 0007 set the region/DR direction but left **exact RPO/RTO numbers deferred to this phase**. Clinical
data loss/downtime is a safety and compliance issue.

## Decision
- **In-region:** Multi-AZ Aurora + Fargate → automatic failover in minutes.
- **Cross-region DR:** `ap-south-2` — Aurora cross-region backups/snapshots, S3 CRR, audit WORM replicated,
  IaC redeployable, Route 53 failover.
- **Targets (proposed this phase):** **RPO ≤ 5 min** (Aurora PITR); **in-region RTO ≤ 30 min**;
  **cross-region RTO ≤ 2 h** (MVP) → ≤ 1 h at scale.
- **Backups:** Aurora automated + PITR + snapshots; S3 versioning + CRR + Object Lock; **restore drills** +
  DR game-days validate targets; backups + restores are **encrypted + audited**.

## Alternatives Considered
- **Backups without tested restores** — false confidence. Rejected (drills required).
- **Hot active-active multi-region now** — cost/complexity unjustified for MVP. Deferred.
- **No cross-region DR** — unacceptable for PHI. Rejected.

## Trade-offs
Cross-region DR adds cost/replication; active-passive is the right MVP balance vs active-active.

## Consequences
Defined, tested recovery posture; the prior RPO/RTO deferral is closed (pending business RTO confirmation).

## Dependencies
