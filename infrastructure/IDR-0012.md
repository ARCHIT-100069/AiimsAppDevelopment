# IDR-0012 — Terraform/IaC + infrastructure governance

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
Reproducibility, review, and drift control are essential for a compliant, multi-account, multi-env PHI
platform (SDR-0012).

## Decision
**Terraform** for 100% of infra; **remote state** (S3 + DynamoDB lock) per account; reusable **modules**;
environments are module instantiations differing by variables (parity). **IaC scanning** (tfsec/checkov) +
plan review in CI; **no ClickOps** in staging/prod; **drift detection**. **SCP guardrails** (region/PHI).
Infra changes that alter topology/security/cost materially are **IDR-worthy**.

## Alternatives Considered
- **CloudFormation/CDK** — viable; Terraform chosen for maturity/multi-cloud portability (Blueprint §3).
- **Manual console (ClickOps)** — unreproducible, drift-prone. Rejected.

## Trade-offs
IaC discipline + state management add process; deliver reproducibility, review, and drift control.

## Consequences
Auditable, reproducible infra; environment parity; governed change.
