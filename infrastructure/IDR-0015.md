# IDR-0015 — Release (blue/green + canary) + autoscaling + cost

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
A 24/7 clinical system needs zero-downtime releases, elastic scaling that never requires re-architecture
(Blueprint §26), and controlled cost — including AI token spend (AIDR-0013).

## Decision
- **Release:** trunk-based + short-lived branches; **immutable image promotion** (build once → dev →
  staging → prod); **feature flags decouple deploy from release** (ADR 0010); rollback = redeploy prior digest.
- **Deploy:** **ECS blue/green via CodeDeploy** with **canary** (e.g. 10% → bake → 100%) and automated
  rollback on alarm; expand/contract DB migrations (DDR 0011) keep schema changes safe.
- **Autoscaling:** ECS target-tracking (CPU/mem/RPS/queue-depth); workers scale on queue depth; Aurora read
  replicas; Serverless v2 for non-prod/bursty.
- **Cost:** Fargate Spot for stateless/non-prod; right-sizing; Savings Plans for steady prod; S3 tiering;
  per-tenant/service cost tags; budgets + anomaly alerts; non-prod auto-stop.

## Alternatives Considered
- **In-place (recreate) deploys** — downtime, risky. Rejected (blue/green + canary).
- **Manual scaling** — slow, over/under-provisioned. Rejected.
- **No cost governance** — runaway spend (esp. AI). Rejected.

## Trade-offs
Blue/green needs double capacity briefly; canary adds bake time; Spot can be reclaimed (stateless only).
All acceptable for zero-downtime + cost control.

## Consequences
Zero-downtime releases, elastic scale, controlled and observable cost.

## Dependencies
Blueprint §26, ADR 0010, DDR 0011, AIDR-0013, IDR-0004/0009.

## Confidence
High. ## Reversibility Medium.

## Phase Classification
