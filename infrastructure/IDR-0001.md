# IDR-0001 — AWS Organizations multi-account + SCP guardrails

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
A PHI platform needs strong isolation between production data and lower environments, and a cap on the
blast radius of a compromised credential (assume-breach, SDR).

## Decision
**AWS Organizations, multi-account:** Management, Security/Log-archive, Shared-services, Dev, Staging,
Production. **SCPs** enforce an India-region allow-list, deny public-S3/PHI egress, and block dangerous
actions. Only Production holds real PHI. Centralized CloudTrail/GuardDuty/Config in the security account.

## Alternatives Considered
- **Single account, IAM/tags only** — weak isolation, easy cross-env mistakes, larger blast radius. Rejected.
- **Per-service accounts** — over-fragmented for a small team now. Deferred.

## Trade-offs
More accounts to manage (mitigated by Terraform + org automation); far stronger isolation and guardrails.

## Consequences
Prod PHI is hard-isolated; SCPs make region/PHI mistakes structurally hard.

## Dependencies
SDR-0008, ADR 0007, IDR-0002/0012.

High. ## Reversibility Medium.
