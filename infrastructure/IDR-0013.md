# IDR-0013 — Observability + monitoring/alerting

**Status:** Accepted · **Version:** 1.0 · **Owner:** Cloud & Infra Architect · **Date:** 2026-07-04

## Context
A 24/7 clinical platform needs end-to-end visibility and actionable alerts, with **no PHI** in telemetry
(SDR-0010, Blueprint §22).

## Decision
**OpenTelemetry** across services → traces (API→workers→AI plane), RED metrics, **structured JSON logs
with correlation + tenant + actor ids and NO PHI**; backends CloudWatch + managed OTel/Grafana. **SLOs +
error budgets** per service; alerts on SLO burn, 5xx spikes, queue backlog, DB/replica lag, **RLS/isolation
anomalies**, **audit-integrity failures**, cost spikes, AI guardrail/eval regressions. Audit archived to WORM
in the security account. Synthetic canaries for the OPD hero flow.

## Alternatives Considered
- **Vendor-locked agents only** — OTel chosen for portability. Rejected as sole approach.
- **Logs only (no traces/metrics)** — insufficient for distributed debugging/SLOs. Rejected.

## Trade-offs
Instrumentation + redaction effort; delivers actionable, PHI-safe observability.

## Consequences
Fast detection/diagnosis; security + reliability signals first-class; no PHI leakage.

## Dependencies
SDR-0010, Blueprint §22, IDR-0001 (log archive).
