# ODR-0003 — Incident response process (severities, postmortems)

**Status:** Accepted · **Version:** 1.0 · **Owner:** SRE/Ops Lead · **Date:** 2026-07-04

## Context
Incidents — especially PHI/patient-safety ones — need a fast, consistent, blameless response with clear roles
and a compliant breach path (SDR-0013).

## Decision
**Severity taxonomy** (SEV1 patient-safety/PHI-breach/full-outage → SEV4 minor) with defined roles (Incident
Commander, Comms, responders), a **detect→declare→triage→mitigate→resolve→postmortem** lifecycle,
**blameless postmortems** (SEV1/2) with tracked actions, and documented **containment levers** (revoke
tokens/keys, isolate tenant/service, rotate secrets, flag off). Suspected PHI breach triggers the DPDP
notification workflow (Board + affected principals within the mandated window).

## Alternatives Considered
- **Ad hoc/heroic response** — inconsistent, slow, unaccountable. Rejected.
- **Blameful culture** — hides problems, kills learning. Rejected.

## Trade-offs
Process + postmortems take time; dramatically improve MTTR, learning, and compliance.

## Consequences
Fast, consistent, auditable incident handling; regulator-ready breach path.

## Dependencies
SDR-0013, ODR-0004, audit (§21), DPDP (§23).

## Confidence
High. ## Reversibility Medium.
