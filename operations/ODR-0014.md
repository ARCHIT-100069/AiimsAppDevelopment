# ODR-0014 — Operational KPIs, continuous improvement & documentation governance

**Status:** Accepted · **Version:** 1.0 · **Owner:** SRE/Ops Lead · **Date:** 2026-07-04

## Context
Operations must be measured and improved over time, and operational docs must stay current — extending the
project's documentation governance into day-2 (GOVERNANCE).

## Decision
- **KPIs:** SLO attainment, error-budget burn, **DORA** (lead time, deploy freq, change-fail rate, MTTR),
  MTTA, incident count/severity, **toil %**, alert-noise ratio, cost per tenant/encounter, audit-integrity
  pass rate, DR-drill success.
- **Continuous improvement:** postmortem actions + game-day findings + KPI trends feed a standing reliability
  backlog; **quarterly operational review** adjusts SLOs, capacity, and automation.
- **Doc governance:** runbooks/playbooks/postmortems are living, versioned, owned git docs (GOVERNANCE §2
  headers), **reviewed after every incident/game-day**; stale runbooks are tracked defects.

## Alternatives Considered
- **Vibes-based ops** — no improvement signal. Rejected (KPIs).
- **Static, unowned runbooks** — rot into uselessness. Rejected (living + reviewed).

## Trade-offs
Metrics + reviews + doc upkeep are ongoing effort; drive measurable reliability improvement.

## Consequences
Data-driven, continuously improving operations with current, trusted documentation.
