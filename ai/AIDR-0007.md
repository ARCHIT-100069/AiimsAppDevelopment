# AIDR-0007 — Prompt architecture (versioned, guardrail, structured)

**Status:** Accepted · **Version:** 1.0 · **Owner:** AI Systems Architect · **Date:** 2026-07-04

## Context
Prompts are effectively code that governs model behavior and safety; they must be reviewed, versioned, and
injection-resistant (SDR-0011).

## Decision
**Versioned prompt templates** (reviewed like code); a strong **system prompt** encodes the Constitution +
refusal rules; **guardrail prompts** constrain scope/format. Retrieved/user content is inserted in
**delimited, clearly-untrusted sections** (AIDR-0009); **no raw PHI in prompts** beyond redacted tokens
(AIDR-0008). Outputs requested in **validated schemas** so they can be checked before use.

## Alternatives Considered
- **Ad hoc inline prompts** — unversioned, unreviewable, injection-prone. Rejected.
- **Free-form output** — unvalidatable. Rejected (schema outputs).

## Trade-offs
Prompt governance + structured I/O add rigor/overhead; essential for safety and evaluability.

## Consequences
Prompts are auditable, testable (AIDR-0012), and resistant to manipulation.

## Dependencies
