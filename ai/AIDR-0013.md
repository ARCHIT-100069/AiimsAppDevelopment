# AIDR-0013 — AI cost optimization, caching & rate limiting

**Status:** Accepted · **Version:** 1.0 · **Owner:** AI Systems Architect · **Date:** 2026-07-04

## Context
LLM usage is a real cost and a potential abuse/DoS vector; spend must be controlled without compromising
PHI (SDR-0004) or fairness across tenants.

## Decision
- **Cost:** right-size models per task (AIDR-0004); prefer small models + RAG; token budgets per
  capability/tenant; bounded chains (max tokens/steps). Cost metered per tenant/capability (AIDR-0011).
- **Caching:** embedding cache (content hash → vector); response cache only for **deterministic, non-PHI**
  prompts, tenant-scoped keys + TTL; **PHI-bearing responses not cached** by default.
- **Rate limiting:** per tenant/user/capability at the gateway (Redis); 429/queue on breach; integrates
  with API limits (APDR-0013).

## Alternatives Considered
- **No budgets/limits** — runaway cost + abuse. Rejected.
- **Cache everything (incl. PHI)** — leak/staleness risk. Rejected (non-PHI only).

## Trade-offs
Budgets/limits can throttle legitimate bursts; caching adds invalidation logic. Worth it for cost/safety.

## Consequences
Predictable AI spend, fair multi-tenant use, no PHI cached unsafely.

## Dependencies
SDR-0004, APDR-0013, AIDR-0004/0011.

## Confidence
High. ## Reversibility Medium.
