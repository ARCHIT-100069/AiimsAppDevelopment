# AIDR-0002 — AI Gateway as single ingress/egress

**Status:** Accepted · **Version:** 1.0 · **Owner:** AI Systems Architect · **Date:** 2026-07-04

## Context
AI must be controllable, auditable, and provider-agnostic; scattered direct model calls would bypass
redaction, audit, and boundaries.

## Decision
A single **AI Gateway** (the `AiGateway` port, BDR-0008) is the only path to any model. It owns provider
abstraction, versioned prompts, **PHI redaction** (AIDR-0008), auth + tenant scoping, guardrails/injection
defense (AIDR-0009), rate limiting, caching, **full audit** (AIDR-0011), and cost accounting. No module
calls a model directly.

## Alternatives Considered
- **Per-module SDK calls** — bypasses redaction/audit/boundaries. Rejected.
- **Thin proxy only** — misses guardrails/governance. Rejected (full gateway).

## Trade-offs
A central gateway is a chokepoint (mitigated by horizontal scale, AIDR-0003); worth it for control.

## Consequences
Uniform enforcement of every AI safety/compliance control; provider swap is contained.

## Dependencies
BDR-0008, SDR-0011, AIDR-0008/0009/0011.
