# AIDR-0009 — AI security + prompt-injection defense

**Status:** Accepted · **Version:** 1.0 · **Owner:** AI Systems Architect · **Date:** 2026-07-04

## Context
Retrieved/user content can carry adversarial instructions (prompt injection) aiming to exfiltrate context
or make the model act outside bounds (SDR-0011). Assume injection will be attempted.

## Decision
- **Untrusted-by-default:** retrieved/user content in delimited, labeled sections; the system prompt forbids
  following instructions embedded in data.
- **Constrained capability:** allowlisted, **read-only** tools; **no write path** to clinical data; bounded
  output schemas validated before use.
- **Output validation + policy checks:** suspicious/boundary-violating outputs are **blocked and audited**
  (AIDR-0011). AI plane is network-isolated with a least-privilege identity; secrets via Secrets Manager.

## Alternatives Considered
- **Trust retrieved content** — classic injection foothold. Rejected.
- **Allow write-capable tools** — lets injection cause harm. Rejected (no write path).

## Trade-offs
Constraints reduce model "freedom"/capability; necessary for a PHI system.

## Consequences
Injection cannot exfiltrate cross-tenant/PHI context or trigger unsafe actions; attempts are logged.

## Dependencies
SDR-0011, AIDR-0002/0007/0011, DDR 0002.
