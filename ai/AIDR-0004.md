# AIDR-0004 — LLM provider strategy, model selection & routing

**Status:** Accepted (provider shortlist deferred) · **Version:** 1.0 · **Owner:** AI Systems Architect
**Date:** 2026-07-04

## Context
PHI + DPDP + India residency constrain which models may see what data; cost/latency vary by task.

## Decision
**Provider-abstracted, model-agnostic.** The gateway **routes by task + sensitivity + cost**: small
in-region models for redaction/classification, mid-tier for drafting/summarization, capable models for
grounded Q&A. **Residency/PHI rule:** models must be **in-region / enterprise no-retention**; endpoints
that cannot meet residency/no-train receive **only redacted, non-PHI** content, else use a
self-hosted/in-region model. Routing rules are config-driven, auditable, with fallback on failure.

## Alternatives Considered
- **Single hard-wired provider** — lock-in + residency risk. Rejected (abstraction).
- **Always largest model** — cost/latency waste. Rejected (task routing).
- **Send raw PHI to any external model** — violates DPDP/SDR-0004. Rejected.

## Trade-offs
Abstraction + routing add complexity; buys privacy compliance, cost control, and no lock-in.

## Consequences
Privacy-respecting, cost-aware model use; provider swap is a config change.

## Dependencies
ADR 0007 (residency), ADR 0010, SDR-0004, AIDR-0002/0008.
