# AIDR-0006 — Vector DB: pgvector (MVP) → dedicated store (scale)

**Status:** Accepted · **Version:** 1.0 · **Owner:** AI Systems Architect · **Date:** 2026-07-04

## Context
RAG needs vector storage/search with strict tenant isolation, without prematurely operating a new datastore
(ADR 0001 spirit; DDR 0002 tenancy).

## Decision
**MVP: `pgvector` in Aurora PostgreSQL** — reuses the frozen DB, so **RLS enforces tenant isolation on
embeddings**, with transactional consistency to source rows. Embedding tables carry `tenant_id` + RLS.
**Scale/Production: dedicated vector store** (e.g. OpenSearch k-NN) fed from the event stream if
volume/latency demands (mirrors the search-promotion path, Blueprint §17).

## Alternatives Considered
- **Dedicated vector DB now (Pinecone/Weaviate)** — new infra + a second tenancy model to secure;
  premature. Deferred.
- **External managed vector store with PHI** — residency/tenancy risk. Rejected for PHI embeddings.

## Trade-offs
pgvector at very large scale trails specialized engines; RLS reuse + zero new infra wins for MVP.

## Consequences
Tenant-isolated embeddings on day one; clean promotion path at scale.
