# SDR-0006 — Secrets management

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
Runtime secrets (DB creds, Keycloak client secrets, provider keys) must never live in code, images, or repo.

## Decision
**AWS Secrets Manager** for all runtime secrets; injected via IAM task roles at runtime; rotation enabled
(DB creds via RDS Proxy). CI/CD uses **OIDC-federated short-lived** cloud credentials — no long-lived keys
in GitHub. Secret scanning in CI blocks committed secrets.

## Alternatives Considered
- Env vars / .env in repo — leak-prone. Rejected.
- SSM Parameter Store only — workable but weaker rotation ergonomics for secrets. Secrets Manager preferred.
- Vault (self-hosted) — extra ops surface; revisit if multi-cloud.

## Trade-offs
Secrets Manager cost + retrieval latency (cached). Negligible vs leak risk.

## Consequences
No secrets in artifacts; rotation and least-privilege access; auditable secret access.

## Dependencies
SDR-0012 (IAM/CI), SDR-0005 (KMS encrypts secrets).
