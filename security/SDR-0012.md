# SDR-0012 — Supply chain & secure SDLC

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
Modern breaches increasingly enter via dependencies, images, and CI. Security must shift left.

## Decision
- **Supply chain:** pinned/locked deps, automated vuln scanning, license checks, **SBOM** per build, image
  scanning, **image signing/provenance (cosign/SLSA)** in Production.
- **Secure SDLC (CI, merge-blocking):** SAST, dependency scan, secret scan, container scan, IaC scan, and
  the **cross-tenant isolation test**. Mandatory code review; **security review** for authz/RLS/crypto/secrets
  changes. Threat modeling per new context/integration. No-PHI-in-logs lint rule.
- **CI identity:** least-privilege OIDC to AWS; protected branches.

## Alternatives Considered
- Manual/periodic scanning — misses regressions. Rejected in favor of gates.
- Trust upstream implicitly — supply-chain risk. Rejected.

## Trade-offs
Gates add pipeline time and can block merges; that is the intended safety behavior.

## Consequences
Vulnerabilities and secrets are caught before release; provenance is verifiable.

## Dependencies
SDR-0003 (isolation gate), SDR-0006 (secret scanning), SDR-0008 (IaC scan).

## Confidence
High.

## Reversibility
Medium.

## Phase Classification
Structural Foundation (CI gates) + Production Implementation (signing/SLSA, SBOM attestation).
