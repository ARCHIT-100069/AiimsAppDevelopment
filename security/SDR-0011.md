# SDR-0011 — AI security boundary controls

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
The AI plane touches PHI-adjacent data and external models; it must be operational-only (Constitution) and
resistant to prompt injection/exfiltration.

## Decision
- AI reached **only** via the `AiGatewayModule` port; **operational-only**, never clinical decisions.
- **PHI redaction/tokenization before any model call**; **tenant-scoped RAG** (no cross-tenant retrieval).
- **Prompt-injection defenses:** untrusted retrieved/user content, constrained tool/output scope, output
  validation; **no AI write path** to clinical records without human sign-off.
- **Full audit** of AI I/O (redacted); AI failure never blocks clinical workflows.

## Alternatives Considered
- Direct model access from modules — bypasses redaction/audit. Rejected.
- Sending raw PHI to external models — unacceptable. Rejected.
- Fine-tuned clinical model as authority — violates Constitution. Rejected.

## Trade-offs
Redaction/gateway add latency and reduce model context; required for safety/compliance.

## Consequences
AI augments operations without becoming a PHI-leak or clinical-authority risk.

## Dependencies
Blueprint §10/§28, SDR-0004 (redaction), SDR-0007 (audit).

## Confidence
High.

## Reversibility
Low (boundary is a hard constraint); Medium for provider choice.

## Phase Classification
Structural Foundation (gateway/boundary) + Production Implementation (real AI plane).
