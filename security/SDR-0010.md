# SDR-0010 — Logging/monitoring & PHI redaction

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
Observability is required (blueprint §22) but logs are a common PHI-leak vector.

## Decision
- **Structured JSON logs** with correlation/tenant/actor IDs; a **redaction pipeline** + lint rule
  guarantee **no PHI or secrets** in logs, metrics, traces, or errors.
- **OpenTelemetry** traces/metrics; security signals surfaced: authN failures, authz denials, rate-limit
  hits, isolation anomalies, audit-integrity failures.
- **Alerting** on security + SLO breaches; **SIEM** integration and anomaly detection in Production.

## Alternatives Considered
- Free-form logging — high PHI-leak risk. Rejected.
- Vendor-locked agents only — OTel chosen for portability (blueprint §22).

## Trade-offs
Redaction adds processing and discipline; essential for PHI safety.

## Consequences
Actionable security telemetry without PHI exposure.

## Dependencies
Blueprint §22, SDR-0007 (audit distinct from logs).

## Confidence
High.

## Reversibility
Medium.

## Phase Classification
Structural Foundation (redaction, OTel) + Production Implementation (SIEM, anomaly detection).
