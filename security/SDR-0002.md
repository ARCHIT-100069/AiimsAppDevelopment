# SDR-0002 — Authorization: RBAC-now, ABAC-ready, PEP/PDP, break-glass

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
Healthcare authorization is domain-specific (role, department, org, resource, and later relationship and
consent). It must be enforced consistently and be extensible without a rewrite.

## Decision
- **RBAC** scoped by user/role/department/organization/resource; **ABAC/ReBAC-ready** policy layer.
- **PEP = NestJS guards; PDP = `packages/authz`** — authorization is centralized, never ad hoc in controllers.
- **Separation of duties:** clinical/billing/admin roles distinct; least privilege by default.
- **Break-glass** emergency access (Production): explicit, time-boxed, heavily audited, review-flagged.
- **Consent-aware access** (Production): cross-provider PHI access can require a valid consent artifact (ADR 0004).

## Alternatives Considered
- Authorization inside controllers — inconsistent, unauditable. Rejected.
- Full ABAC/policy-engine (OPA) now — premature complexity for MVP; kept as an evolution path.
- IdP-side authorization only — too coarse for clinical authz. Rejected.

## Trade-offs
Central PDP adds indirection; break-glass adds an audited emergency path. Worth it for consistency/safety.

## Consequences
Uniform, testable authorization; clean extension to ABAC/consent-aware without touching endpoints.

## Dependencies
Blueprint §11, ADR 0004 (consent), SDR-0007 (audit).

## Confidence
High.

## Reversibility
Medium — model is extensible; swapping the PDP engine is contained to `packages/authz`.

## Phase Classification
Structural Foundation (RBAC + PEP/PDP) + Production Implementation (break-glass, consent-aware, ABAC).

## Related Documents
SECURITY-BLUEPRINT §5, ADR-0004.
