# SDR-0003 — Tenant isolation defense-in-depth

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
Cross-tenant PHI leakage is the crown-jewel risk. Isolation cannot rest on application discipline alone.

## Decision
Layered isolation, database-anchored: (1) Postgres **RLS with FORCE**, fail-closed on unset context;
(2) **non-privileged `aiims_app`** role (no owner, no BYPASSRLS); (3) **transaction-scoped `SET LOCAL
app.tenant_id`** (pool-safe); (4) **tenant-scoped FKs/uniques** (DDR 0008); (5) **mandatory cross-tenant
isolation CI gate**; (6) **dedicated-DB promotion** for the most sensitive tenants.

## Alternatives Considered
- App-layer `WHERE tenant_id` only — one bug leaks PHI. Rejected as primary control.
- Schema/DB-per-tenant for everyone — heavy at scale; kept only as promotion (ADR 0002).

## Trade-offs
Every access path must set tenant context (fails closed if missed). Small cost for engine-level guarantee.

## Consequences
Cross-tenant access is structurally prevented and continuously tested.

## Dependencies
DDR 0002/0003/0008/0011, DB §17 isolation harness.

## Confidence
High.

## Reversibility
Very low — foundational; changing it is a §6 flaw process event.

## Phase Classification
Structural Foundation.

## Related Documents

## Review Trigger
