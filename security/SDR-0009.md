# SDR-0009 — API security controls

**Status:** Accepted · **Version:** 1.0 · **Owner:** Security Architect · **Date:** 2026-07-04

## Context
The API is the primary attack surface for PHI; controls must be uniform and unbypassable.

## Decision
- **Global middleware:** authN, authZ, tenant-context, and audit-emit on every request — no endpoint opts out.
- **Input validation** via shared Zod contracts (`packages/api-contracts`), reject-by-default.
- **Rate limiting/quotas** (Redis) per tenant/user/IP; per-endpoint **query timeouts**.
- **Idempotency keys** on mutating clinical endpoints; **error envelope never leaks PHI/stack traces**.
- **Security headers** (HSTS, CSP, etc.), strict CORS allowlist, TLS 1.2+.

## Alternatives Considered
- Per-controller ad hoc checks — inconsistent, bypass-prone. Rejected.
- GraphQL surface now — extra authz/caching complexity; deferred (blueprint §13).

## Trade-offs
Strict validation/limits can reject edge cases; correct for a PHI API.

## Consequences
Consistent, testable API security; reduced injection/DoS/leak risk.

## Dependencies
Blueprint §13, SDR-0001 (authN), SDR-0002 (authZ), SDR-0010 (redaction).
