# BDR-0008 — Integration ports & adapters (mock default + feature flags)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Principal Engineer · **Date:** 2026-07-04

## Context
ADR 0010 mandates integrations behind stable interfaces with mocks/flags. The backend must make external
systems (ABDM, consent, payments, notifications, AI) swappable without touching domain code.

## Decision
Each external system is a **port (domain interface)** with an **adapter impl** selected by **feature flag**;
the **default is a mock**. Ports: `ConsentProvider`, `AbdmGateway`, `PaymentGateway`, `NotificationSender`,
`AiGateway`. Adapters own protocol, retries/timeouts, **PHI redaction before egress** (SDR-0004/0011), and
mapping (domain→FHIR at the ABDM adapter, ADR 0003). No module calls an external system directly.

## Alternatives Considered
- **Direct SDK calls in services** — couples domain to vendors, bypasses redaction/audit. Rejected.
- **Real integrations in MVP** — violates the prototype strategy (ADR 0010). Rejected.

## Trade-offs
Port/adapter indirection + mock maintenance; buys demoability now and clean production swap later.

## Consequences
Full product experience demoable with mocks; mock→real is a config change; egress is redacted/audited.

## Dependencies
ADR 0010/0004/0006, SDR-0011, BDR-0002.

## Confidence
High. ## Reversibility Low.

## Phase Classification
Structural Foundation (ports) + MVP (mocks) + Production Implementation (real adapters).
