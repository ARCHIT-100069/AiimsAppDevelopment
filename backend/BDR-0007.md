# BDR-0007 — Background jobs on BullMQ

**Status:** Accepted · **Version:** 1.0 · **Owner:** Principal Engineer · **Date:** 2026-07-04

## Context
Slow/async work (notifications, FHIR bundle generation, projections, retention sweeps) must run off the
request path, reliably, and under tenant isolation.

## Decision
**BullMQ on Redis** (Blueprint §15). At-least-once, **idempotent handlers**, exponential backoff, **DLQ**,
repeatable (cron) jobs. **Workers set tenant context** (`SET LOCAL app.tenant_id` from the job payload) —
RLS applies to workers exactly as to the API (SDR-0003). Workers are separate Fargate services scaling
independently.

## Alternatives Considered
- **In-process async only** — lost on crash, no retries/backpressure. Rejected.
- **SQS/Kafka now** — heavier ops than needed; migration path kept for scale. Deferred.
- **pg-boss** — keeps queue load on the primary DB. Rejected (reuse existing Redis).

## Trade-offs
Redis as a critical dependency; job idempotency discipline required.

## Consequences
Reliable async processing, tenant-safe, independently scalable.

## Dependencies
Blueprint §15, SDR-0003, BDR-0004/0005.

## Confidence
High. ## Reversibility Medium.

## Phase Classification
Structural Foundation (core families) + Production Implementation (retention/SIEM/ABDM async).
