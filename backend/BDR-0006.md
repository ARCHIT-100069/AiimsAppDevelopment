# BDR-0006 — CQRS-lite (read-model projections, not event sourcing)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Principal Engineer · **Date:** 2026-07-04

## Context
Some reads (dashboards, worklists, search) are expensive and shouldn't burden the write model; but full
event sourcing adds significant complexity and consistency burden.

## Decision
**CQRS-lite:** commands mutate via aggregates + repositories; Postgres stays the system of record (no event
sourcing). Simple reads hit tenant-scoped indexed tables directly; **expensive reads use read-model
projections** built from domain events and served from read replicas (`aiims_readonly`). Projections are
rebuildable by replaying the event stream.

## Alternatives Considered
- **Full event sourcing** — powerful but heavy; consistency/debugging cost too high for MVP. Rejected.
- **All reads off the write tables** — hurts under dashboard/search load. Partially rejected (only for
  expensive reads).

## Trade-offs
Projections add eventual consistency and rebuild logic for the read side; keeps writes simple and reads fast.

## Consequences
Read/write separation where it pays off; scale path via replicas (Blueprint §26) without re-architecture.

## Dependencies
BDR-0005 (events), Blueprint §26, DDR 0010 (partitioning for heavy tables).

## Confidence
High. ## Reversibility Medium.

## Phase Classification
MVP Implementation (few projections) + Production Implementation (more read models).
