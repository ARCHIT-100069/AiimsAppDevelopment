# BDR-0003 — Repository pattern & Drizzle confinement

**Status:** Accepted · **Version:** 1.0 · **Owner:** Principal Engineer · **Date:** 2026-07-04

## Context
ADR 0011 chose Drizzle but kept Prisma as a fallback and required the ORM to stay in `packages/db`. The
backend must not let ORM types leak, and every query must run under tenant context (DDR 0002).

## Decision
**Repository ports in the domain; impls in `infrastructure/`** delegating to `packages/db`. Repositories
expose intention-revealing methods and return **domain objects, not ORM rows**. All calls run inside a
tenant-context transaction (BDR-0004). Read projections use `aiims_readonly`/replicas.

## Alternatives Considered
- **Drizzle used directly in services** — leaks ORM, defeats the fallback, scatters tenant handling. Rejected.
- **Generic repository/`find(any)`** — unreviewable queries, index misuse. Rejected for explicit methods.

## Trade-offs
Mapping row↔domain is extra code; buys portability, testability, and query discipline.

## Consequences
ORM swap stays survivable; queries are reviewable and indexed (DB §12); tenant context guaranteed.

## Dependencies
ADR 0011, DDR 0002/0011, BDR-0004.
