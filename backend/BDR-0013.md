# BDR-0013 — Dependency-direction enforcement (ports & adapters, import boundaries)

**Status:** Accepted · **Version:** 1.0 · **Owner:** Principal Engineer · **Date:** 2026-07-04

## Context
Layering (BDR-0001), module boundaries (BDR-0002), and ORM confinement (BDR-0003) only hold if enforced
mechanically — good intentions erode under delivery pressure.

## Decision
Dependencies flow **inward** (`api → application → domain ← ports ← infrastructure`); everything may depend
on `domain-types`; nothing depends on an app. **Enforced in CI** via ESLint import-boundary rules and the
Turborepo dependency graph. Domain has **no** imports of NestJS, Drizzle, or HTTP. Violations fail the build.

## Alternatives Considered
- **Convention/docs only** — erodes without enforcement. Rejected.
- **Runtime DI checks** — too late; CI static enforcement preferred.

## Trade-offs
Up-front lint/config and occasional friction when refactoring; guarantees architectural integrity long-term.

## Consequences
Boundaries and the ORM fallback stay intact for the platform's life; onboarding is safer.
