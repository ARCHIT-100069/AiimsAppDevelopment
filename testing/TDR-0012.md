# TDR-0012 — CI/CD quality gates + coverage policy + release gates

**Status:** Accepted · **Version:** 1.0 · **Owner:** QA/Eng Lead · **Date:** 2026-07-04

## Context
Quality must be enforced automatically at the pipeline (IDR-0011), with coverage that measures the right
code and release gates that prevent unsafe go-lives.

## Decision
- **Ordered blocking gates:** lint → typecheck → unit → component → **integration (RLS)** → **isolation
  gate** → contract → **AI safety/eval gate** → SAST/DAST/dep/secret/container/IaC → build → E2E → perf
  smoke → canary deploy.
- **Coverage:** risk-based — **domain/critical ≥ 90%**, **overall ≥ 80%**, **new code ratchet** (must not
  lower). No coverage theater.
- **Release gates:** all green + coverage met + isolation/AI-safety/security passed + E2E OPD green + perf
  within budget + no open criticals + reviews approved. Feature flags gate risky features (ADR 0010).

## Alternatives Considered
- **Non-blocking/advisory gates** — ignored, quality erodes. Rejected.
- **Blanket coverage % only** — gameable, misleading. Rejected (risk-based + ratchet).

## Trade-offs
Strict gates slow some merges/releases — the intended safety property for PHI/clinical software.

## Consequences
Consistent, enforced quality; unsafe releases are blocked.

## Dependencies
IDR-0011, TDR-0006/0007/0008, all test types.

High. ## Reversibility Medium.
