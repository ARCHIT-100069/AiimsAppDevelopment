# TDR-0014 — Test environments, observability, metrics & production exit criteria

**Status:** Accepted · **Version:** 1.0 · **Owner:** QA/Eng Lead · **Date:** 2026-07-04

## Context
Testing needs consistent environments, visibility into quality trends, and an explicit, non-negotiable
bar for going to production with PHI.

## Decision
- **Environments:** local Testcontainers, CI ephemeral, and staging (prod-like, synthetic) — same Terraform
  modules for parity (IDR-0002); **no PHI outside prod**.
- **Test observability:** dashboards for pass/flake rate, coverage ratchet, mean test time, escaped-defect
  rate, gate-failure reasons.
- **Quality metrics:** DORA + defect density + a11y/perf/SLO compliance + AI eval scores + isolation-gate
  history.
- **Production exit criteria (go-live checklist):** all release gates green; **isolation suite green**;
  **AI safety evals green**; security scans clean + **pen-test criticals closed**; **DR + restore drill
  passed**; **WCAG 2.1 AA** on OPD; perf within SLOs; audit integrity verified; go-live-scope DPDP/ABDM
  items resolved; Ops runbooks in place. **No red criterion → no go-live.**

## Alternatives Considered
- **Ad hoc "feels ready" go-live** — unsafe for PHI/clinical. Rejected (explicit checklist).
- **Environments configured by hand** — drift. Rejected (Terraform parity).

## Trade-offs
A hard exit checklist can delay launch; that is the point for a healthcare platform.

## Consequences
Clear, measurable quality; a defensible, safety-first go-live decision.
