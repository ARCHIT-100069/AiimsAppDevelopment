# TDR-0004 — Contract testing (api-contracts + event-schemas)

**Status:** Accepted · **Version:** 1.0 · **Owner:** QA/Eng Lead · **Date:** 2026-07-04

## Context
Contract-first APIs (APDR-0014) and versioned events (BDR-0005) only stay drift-free if verified in CI.

## Decision
Validate server + typed client against `api-contracts`/OpenAPI (breaking changes fail CI and gate a version
bump per APDR-0002); validate outbox/event payloads against `event-schemas`. Consumer-driven contracts for
external partners/webhooks (Production). Includes the FHIR boundary contract (CapabilityStatement).

## Alternatives Considered
- **Manual API review only** — misses drift. Rejected.
- **No event contracts** — risky future service split. Rejected.

## Trade-offs
Contract maintenance adds a step; prevents client/server and producer/consumer drift.

## Consequences
No API/event drift; safe evolution and future service extraction.

## Dependencies
APDR-0002/0014, BDR-0005, TDR-0008.

## Confidence
High. ## Reversibility Medium.

## Phase Classification
Structural Foundation.
