# TDR-0010 — Accessibility, mobile & cross-browser testing

**Status:** Accepted · **Version:** 1.0 · **Owner:** QA/Eng Lead · **Date:** 2026-07-04

## Context
A clinical tool must be accessible, work across the supported browser matrix, and behave natively on
iOS/Android (FEDR-0004/0002).

## Decision
- **Accessibility:** automated axe checks in component + E2E; manual screen-reader passes for critical
  flows; **WCAG 2.1 AA** as a release criterion for the OPD flow.
- **Mobile:** RN unit/component + **Detox/Maestro E2E** on an iOS/Android device matrix; secure-storage,
  offline-cache, biometric/permissions, OTA-update safety.
- **Cross-browser:** Playwright across Chromium/Firefox/WebKit + responsive breakpoints.

## Alternatives Considered
- **A11y as a manual afterthought** — inconsistent, non-compliant. Rejected (automated + gated).
- **Single-browser testing** — misses engine-specific bugs. Rejected.

## Trade-offs
Device/browser matrices add CI time/cost; required for an inclusive, cross-platform clinical app.

## Consequences
Accessible, cross-browser, native-quality clients verified each release.

## Dependencies
FEDR-0002/0004, TDR-0005, IDR-0011.

## Confidence
High. ## Reversibility Medium.

## Phase Classification
Structural Foundation.
