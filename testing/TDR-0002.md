# TDR-0002 — Unit testing (pure domain, Vitest/RTL)

**Status:** Accepted · **Version:** 1.0 · **Owner:** QA/Eng Lead · **Date:** 2026-07-04

## Context
Business rules live in the domain layer (BDR-0001) and must be fast and deterministic to test.

## Decision
**Vitest/Jest** for pure **domain** logic (aggregates, value objects, invariants) — no IO; mocks only at
ports. Frontend units via React/RN Testing Library. High coverage of the domain (§26), pragmatic elsewhere.

## Alternatives Considered
- **Testing through the DB/HTTP for unit-level logic** — slow, coupled. Rejected (pure units).
- **Heavy mocking of internals** — brittle. Rejected (mock only boundaries).

## Trade-offs
Pure domain requires clean layering (already BDR-0001); yields fast, stable tests.

## Consequences
Fast feedback on the rules that matter; safe refactoring.

## Dependencies
Backend §4/§18, TDR-0001.

High. ## Reversibility Medium.
